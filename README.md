# Pygmalion · DroneGen

Студия фигур для дрон-шоу: **чат → картинка → точная 3D-модель → Blender**. Всё работает на вашем компьютере,
без облака и без интернета после установки.

```
Blender ──Alt+Shift+D──▶ окно «DroneGen Studio» (чат, проекты, 3D-просмотр, ползунки)
   ▲                              │ HTTP + SSE
   └──────── «В Blender» ◀── сервер 127.0.0.1:8188 ──▶ чат:      Qwen3-VL-8B (llama.cpp), локально
                              одна очередь, одна GPU     ├ картинки: Z-Image-Turbo / SDXL
                                                         ├ 3D:       Hunyuan3D-2mv / mini, TripoSR, силуэт
                                                         └ чертежи:  домбра, шанырак, юрта, Байтерек
```

Готовая модель появляется в коллекции **DroneGen** в начале координат, выделенной и активной — дальше на ней можно
расставлять точки формации (например, кнопкой Pointille «Распределить вершины»).

## Три пути к модели

| Путь | Когда | Точность | Время на RTX 3050 |
|---|---|---|---|
| **Точный чертёж** | предмет из списка (домбра, шанырак, юрта, Байтерек) | ровные формы, нужное число деталей (у домбры ровно 2 колка) | < 1 с, без видеокарты |
| **Лист из 4 видов → Hunyuan3D-2mv** | любой предмет | высокая: форма по видам спереди, сбоку и сзади | ~1,5 мин на лист + 25 с на 3D |
| **Одна картинка → Hunyuan3D-mini / TripoSR / силуэт** | быстрый черновик | средняя / грубая | 10–30 с |

Почему так: нейросеть по одной картинке не знает, что сзади, и «сглаживает» форму. Домбра по картинке TripoSR
получилась «яйцом» (толщина 0,65 ширины вместо 0,3–0,5), а Z-Image упорно рисует её как китайскую пипу с четырьмя
колками — этого не лечит ни точный промпт, ни проверка. Замеры и картинки «было / стало» — в
[docs/BENCHMARKS.md](docs/BENCHMARKS.md).

## Требования

| | |
|---|---|
| ОС | Windows 10/11 (основная), Linux; macOS — только силуэт, чертежи и тест |
| Видеокарта | NVIDIA с 6–8 ГБ VRAM и драйвером с CUDA 12.6+ — для нейросетей. Без видеокарты работают чертежи и «силуэт → 3D» |
| Память | 16 ГБ RAM минимум, 32 ГБ рекомендуется (Z-Image и Hunyuan3D на пиках берут до 11–15 ГБ) |
| Blender | 4.2 или новее (проверено на 5.2.1 LTS) |
| Браузер | Edge или Chrome — для окна студии (иначе откроется браузер по умолчанию) |
| Диск | ~45 ГБ: веса ~37 ГБ, PyTorch с CUDA, Python |
| Интернет | только при установке; после неё всё работает офлайн. По желанию — поиск в Википедии, как выглядит незнакомый персонаж (без интернета ассистент спросит описание или картинку) |

## Установка — одна команда

Нужен любой Python 3.9+ (только чтобы запустить установщик; сервер получит свой Python 3.12).
Запускайте из обычного терминала (cmd, PowerShell, Windows Terminal) в папке проекта:

```bash
python install.py
```

Установщик:

1. проверяет компьютер (GPU, VRAM, версию CUDA драйвера, RAM, файл подкачки, диск, Blender) и печатает рекомендации;
2. скачивает [uv](https://github.com/astral-sh/uv) и Python 3.12 в `runtime\`, создаёт там venv;
3. ставит PyTorch под ваш драйвер (cu130 для драйверов с CUDA 13, cu126 — для старых), сервер и зависимости —
   проверенные версии из `server\requirements\lock-win-cu130.txt`;
4. берёт код TripoSR и Hunyuan3D-2 на закреплённых коммитах (их `requirements.txt` не используются, см. ниже);
5. скачивает веса (~37 ГБ, можно прервать — повторный запуск продолжит): Z-Image-Turbo, Hunyuan3D-2mini и 2mv,
   TripoSR, SDXL (запасная), локальная модель чата Qwen3-VL-8B и llama.cpp;
6. пишет `runtime\config.json`, `runtime\start_server.bat` и `runtime\start_studio.bat` и создаёт ярлык
   **DroneGen Studio** (рабочий стол и меню «Пуск»);
7. проверяет всё в **офлайн-режиме** (сеть на время проверки запрещается);
8. собирает аддон инструментами Blender и ставит его в Blender (Extensions → user_default) с включением.

Всё, кроме аддона в самом Blender, лежит в папке проекта, в `runtime\` (она не попадает в git).

| Параметр | Что делает |
|---|---|
| `--skip-sdxl` | не качать запасную модель SDXL (−7 ГБ) |
| `--skip-llm` | не качать локальную модель чата (−6 ГБ): тогда чат только через облако |
| `--profile light` | без PyTorch и нейросетей: только чертежи, «силуэт → 3D» и тест (выбирается сам, если GPU нет) |
| `--cuda cu126` | другая сборка PyTorch (`auto`, `cu132`, `cu130`, `cu126`, `cpu`) |
| `--blender "C:\...\blender.exe"` | путь к Blender, если он установлен не в стандартное место |
| `--no-addon` / `--skip-models` / `--no-selfcheck` | пропустить шаг |
| `--dev` | код сервера из этой папки (editable) — для разработки |
| `--unlocked` | свежие версии пакетов вместо проверенных |

> Если во время установки Blender открыт — перезапустите его. Если вкладки DroneGen нет:
> Edit → Preferences → Add-ons → включите **DroneGen**. Ставить аддон вручную: Edit → Preferences →
> Get Extensions → ⌄ → **Install from Disk…** → `runtime\addon\dronegen-0.8.0.zip`.
>
> Не запускайте установщик из «песочницы» приложений из Microsoft Store (в том числе из терминала таких
> приложений): Windows перенаправит запись в AppData в папку приложения, и Blender не увидит аддон.

## Запуск — один клик

Установщик создаёт ярлык **DroneGen Studio** на рабочем столе и в меню «Пуск» (его находит поиск Windows, его можно
закрепить на панели задач). Клик по нему:

1. запускает сервер **без чёрного окна консоли**;
2. открывает окно студии как отдельное приложение;
3. **закрыли окно — сервер остановился** и освободил видеокарту. Повторный клик, пока сервер уже работает, просто
   открывает окно.

Выключить сервер, не закрывая окно, можно кнопкой «Выключить сервер» в настройках студии (шестерёнка).
Ярлык можно пересоздать: `runtime\venv\Scripts\python -m dronegen_server --home runtime --make-shortcuts`.

Другие способы:

* **Из Blender: Alt+Shift+D** (или кнопка **Открыть студию** в панели DroneGen) — запускает сервер, если он
  выключен, и открывает окно студии. Клавишу можно поменять в настройках аддона (шестерёнка в заголовке панели) или
  в Preferences → Keymap → Window → «Открыть студию».
* `start_studio.bat` — то же, что ярлык, но с окном консоли (видны логи).
* `start_server.bat` — только сервер без окна студии; параметры (`--port 8189`, `--device cpu`, `--online`…) —
  `start_server.bat --help`.

## Студия

Отдельное окно без вкладок браузера: проекты и чаты слева, диалог в центре, «Фигура» справа. В узком окне боковые
панели выезжают кнопками в шапке.

**Диалог.** Опишите фигуру по-русски — «беркут с раскрытыми крыльями», «машинки в мультяшном стиле». Если от
уточнения зависит результат, ассистент задаст 1–3 вопроса кнопками (стиль, поза, вид, цвета). Затем промпт-инженер
пишет точное **английское** описание, и дальше всё идёт само.

**Незнакомые персонажи.** Если в запросе назван конкретный персонаж, бренд или здание («Молния Маквин», «Губка
Боб», «Эйфелева башня»), ассистент сначала ищет его в Википедии (русской и английской). Карточка **«Справка»**
показывает картинку и начало статьи, а промпт-инженер описывает по картинке внешний вид: так нейросеть картинок рисует
то, чего не знает по имени. Опечатки не мешают: «молния маквин» находит «Молния Маккуин». Если интернета нет (или
поиск выключен в настройках), в чате появляется предупреждение и вопрос: **«Опишу словами»** (курсор встанет в поле
ввода), **«Прикреплю картинку»** (откроется выбор файла) или **«Делай как понимаешь»**. Описание и картинка
сохраняются как справка этого чата и сами попадают в бриф. Для казахских предметов есть встроенные справки — там
интернет не нужен.

Дальше:

1. **Бриф** — английский промпт, стиль картинки, способ 3D, список проверок («ровно 2 колка») и число крупных
   деталей, которые программа сверит с картинкой. Для известных предметов (домбра, кобыз, тулпар, шанырак, юрта,
   Байтерек, беркут, Золотой человек, саукеле, ирбис) в описание подмешивается справка: что должно быть и какие
   ошибки обычно делают нейросети.
2. **Точный чертёж** — если для предмета он есть, ассистент строит модель сразу. Справа появляются **ползунки**
   (длина, ширина корпуса, число ладов, грани спинки…): двигаете — модель перестраивается за долю секунды, без
   участия языковой модели.
3. **Картинки** (если чертежа нет или вы просите рисунок) — 2 варианта на выбор. Способ задаёт переключатель
   **«Точность 3D»** над полем ввода:
   * **Авто** — ассистент выбирает сам (для известных предметов — по справке);
   * **1 картинка · быстро** — один объёмный рисунок → Hunyuan3D-mini. Форма сзади и сбоку угадывается;
   * **Лист 4 вида · точно** — **один рисунок с четырьмя видами одного и того же предмета**: спереди, слева, сзади,
     справа. Один лист, а не четыре отдельные картинки, потому что в отдельных нейросеть не слушается «вид сзади» и
     «вид справа» (проверено, [docs/BENCHMARKS.md](docs/BENCHMARKS.md)), а на листе предмет остаётся тем же.
     Лист режется на карточки, и **какой это вид, определяется по самой фигуре, а не по её месту**: Z-Image рисует
     оба профиля в одну сторону, повторяет вид спереди или сзади, рисует 5 фигур вместо 4. Поэтому с листа берутся
     три вида — спереди, сбоку (какой это бок, Hunyuan3D определяет сам, пробуя обе стороны) и сзади, — а повторы
     отбрасываются; под вариантом пишется, что взято и чего нет. Тень на полу не мешает; если виды касаются
     (раскрытые крылья), лист режется по самым узким местам. Если вида сбоку нет, 3D строится по виду спереди —
     выберите другой вариант или «Ещё варианты». Для фигур с очень широким размахом надёжнее «1 картинка».

   Арт-директор считает крупные детали на каждой картинке; картинка с неверным числом деталей помечается красным.
4. **3D-модель** — Hunyuan3D-2mv по карточкам (если есть одна боковая — сторону определяет сам по лучшему совпадению),
   чистка сетки. **Цвета** берутся с карточек с учётом того, что закрыто другими частями, а не просвечивает насквозь:
   не видимое ни с одной карточки (спина, бока по одной фронтальной картинке) достраивается от соседних участков,
   светлая кайма вырезанных краёв не переносится на модель. Превью спереди, 3/4 и сбоку возвращается ассистенту.
5. **В Blender** — кнопка или Ctrl+B: модель попадает в очередь, аддон в открытом Blender забирает её и
   импортирует в коллекцию DroneGen.

**Свои фото.** Прикрепите скрепкой, перетащите в окно или вставьте из буфера. Одно фото используется как картинка для
3D. **2–4 фото одного предмета с разных сторон:** под каждым появляется выбор ракурса (спереди, слева, сзади, справа;
по умолчанию он подставляется по порядку, его можно поправить). Фото склеиваются в **один лист**, он показывается в
ленте, и по нему строится модель (Hunyuan3D-2mv): это самый точный путь, потому что виды настоящие, а не нарисованные.

Клавиши: **Enter** — отправить, **Shift+Enter** — новая строка, **Ctrl+K** — новый чат, **Ctrl+B** — модель в Blender.
История хранится в `runtime\studio\studio.db` (SQLite); чаты можно искать, закреплять, переименовывать.

### Локально или облако

По умолчанию диалог ведёт **локальная модель Qwen3-VL-8B** (llama.cpp, ~6 ГБ видеопамяти, ~25 токенов/с): она
понимает и картинки. Видеокарта одна, поэтому сервер останавливает модель чата на время тяжёлых задач (Z-Image,
Hunyuan3D) и запускает снова (~10 с).

В настройках студии (шестерёнка) можно переключиться на **облако — Claude API**: быстрее и умнее, но тогда текст
чата и картинки уходят в Anthropic. Ключ вводится в окне настроек и хранится только в `runtime\studio\secrets.json`.
Если облако недоступно, диалог продолжается на локальной модели. Без включённого режима «Облако» текст чата и
картинки не покидают компьютер (при поиске персонажа в Википедию уходит только его название — см. ниже).

Локальная модель с 8 млрд параметров ошибается там, где её не ограничивают: придумывает параметры инструментов,
соглашается с неверной картинкой, пишет «отправляю» и не отправляет. Поэтому важное решается кодом, а не моделью:
стиль и способ 3D берутся из брифа и из слов пользователя, детали считает программа, «В Blender» — кнопка.

## Blender

**Студия** (Alt+Shift+D) — основной способ. Панель **N → DroneGen** остаётся для ручной работы:

- **Открыть студию** — большая кнопка сверху, под ней текущая горячая клавиша. Кнопка со значком рабочей области
  переключает Blender на воркспейс **DroneGen** (картинка слева, 3D справа, структура и свойства; сцена и режим объекта
  не меняются — воркспейс собирается при первом открытии из встроенного «Texture Paint»);
- **Сервер** — карточка состояния: *работает* (видеокарта, занятая видеопамять, какая модель в памяти, задачи в
  очереди; кнопки «Освободить VRAM» и «Остановить»), *не запущен* (кнопка **Запустить сервер**) или *ошибка* с
  причиной. Состояние обновляется само: сервер, запущенный ярлыком студии, панель замечает за несколько секунд.
  Цветная точка в заголовке панели показывает то же самое, когда панель свёрнута;
- **Принимать модели из студии** — выключатель импорта по кнопке «В Blender»; под ним последняя пришедшая модель
  (стрелка выделяет её и показывает во вьюпорте);
- **Картинка** — промпт (готовые промпты — в меню справа от поля), **стиль** кнопками (объёмный / 4 вида / плоский /
  без стиля) с подсказкой, под какой способ 3D он готовит картинку; модель, размер, шаги и seed — в свёрнутом блоке
  «Параметры» → **Сгенерировать**;
- **Галерея** — крупное превью (клик по нему — все картинки сеткой), листание ◀ ▶, «Открыть в Image Editor», удалить;
- **3D-модель** — картинка из галереи или файл, способ (Hunyuan3D-mini, Hunyuan3D-mv для листа из 4 видов, TripoSR,
  «Силуэт → объём», тест), **Поверхность** (как есть / гладко / low-poly) и **Симметрия** для Hunyuan3D, размер в
  сцене; разрешение сетки, фон и упрощение — в «Параметрах» → **Сделать 3D-модель**.

- **Анимация** — скелет для выбранной модели (можно выбрать сам меш, его точки дронов Pointille или его скелет):
  **план тела** (Авто, четвероногое, крылатое четвероногое, птица, двуногое с руками, с крыльями, без конечностей,
  предмет) и **метод** → **Построить скелет**. Сервер находит ноги, крылья, руки, шею с головой и хвост и ставит
  кости с понятными именами (`leg_front_2.L`, `wing_1.R`, `tail_3`, меч в руке — `prop.R`). С галочкой
  «Сразу привязать» меш и точки дронов сразу двигаются вместе с костями. Кнопки: **Править** (суставы, левая и
  правая стороны зеркально), **Поза** (попробовать позы), **Привязать** (после правки или новых точек Pointille),
  сбросить позу, удалить скелет.
- **Слои анимации** — движения из каталога сервера, которые подходят этому скелету (взмах крыльями, парение, шаг,
  рысь, галоп, шаг двуногого, волна хвостом, дыхание, взгляд по сторонам, кивок, покачивание, вращение, позы
  «крылья вверх», «на дыбы», «голова влево»…, разовые «взмах мечом» и «прыжок»), и **полёт** по кругу, прямо или по
  своей кривой. У слоя — кадры начала и конца, период, размах, сила, плавный вход и выход. Слои складываются:
  крылья машут, ноги скачут, хвост вьётся, фигура летит — всё одновременно; поза с плавным входом — это переход.
  **Применить** — сервер рассчитывает движения для этого скелета, каждый слой становится дорожкой NLA «DG· …»
  (свои дорожки и действия не трогаются). Точки дронов летят вместе с фигурой.
- **Эффекты формы** — слой, который двигает сами точки дронов поверх костей (Geometry Nodes после Armature, число
  и порядок точек те же): волна по телу, пульс, дрожь, рассыпаться и собраться. Сила слоя плавно входит и выходит.
- **Эффекты со своими дронами** — отдельный объект-точки со своими дронами в той же формации: звезда, кольцо,
  сердце, расходящееся кольцо (волна от удара копытом, по горизонтали), искры, брызги, **след движения** (дроны
  встают вдоль пути кончика крыла, меча или копыта и загораются, когда он проходит) и любая модель из сцены.
  Эффект висит над фигурой и летит с ней, стоит у кончика её части или остаётся на месте в небе. До начала и после
  конца его дроны ждут в **резерве** — сетке прямо позади фигуры на высоте эффекта (у каждого эффекта своя полоса
  резерва) — и перелетают на места плавно; время перелёта аддон сам удлиняет до пределов скорости и ускорения
  Skybrush и пишет об этом. Размер — в метрах в небе, как бы ни была масштабирована фигура; меньше разумного (звезда
  меньше 4 безопасных расстояний) не бывает: при смене вида эффекта размер подтягивается. В панели — **бюджет
  дронов**: фигура + эффекты = сколько нужно.
- **Свет по частям тела** — при привязке у точек дронов появляются группы частей «DG· крыло (левое)», «DG· хвост»…,
  атрибуты `dg_part` (номер части) и `dg_along` (0 у корня части, 1 у кончика — волна света вдоль крыла); у дронов
  эффекта — `dg_on` и `dg_off` (когда каждый загорается и гаснет). Их читают световые эффекты (Pointille).
- **Проверка дронов** — скорость по горизонтали, подъём, спуск, ускорение и расстояние между всеми точками дронов
  сцены на всём протяжении анимации; пределы — из настроек безопасности Skybrush. Для каждого нарушения — кадр и
  часть тела, и кнопка «Замедлить в N раз» (скорости падают в N раз, ускорения — в N²). Если дроны тесно стоят
  уже в покое, проверка так и пишет: фигура мала для своего числа точек.

Под кнопками — прогресс задач с отменой и последний результат; ошибки собираются в одном блоке под карточкой
сервера. Шестерёнка в заголовке панели открывает настройки аддона: адрес и токен сервера, папка сервера и кнопки
запуска и остановки, приём моделей из студии, горячая клавиша студии, папка кэша.

Импортированная модель — один меш с цветами вершин (Material Preview или Solid → Color: Attribute), смотрит в вид
спереди (Numpad 1).

## Типичные ошибки

| Что видно | Почему | Что сделать |
|---|---|---|
| «Нет связи с сервером …» | сервер не запущен или другой адрес | **Запустить сервер** / `start_studio.bat`; адрес — в Preferences → Add-ons → DroneGen |
| «Порт 8188 занят …» в окне сервера | уже запущен другой сервер (8188 использует и ComfyUI) | `start_server.bat --port 8189` и этот адрес в настройках аддона |
| «Локальная модель не запустилась …» | видеопамять занята другими программами | закройте лишнее (EasyDiffusion, ComfyUI, игры); сервер сам освобождает память от своих моделей |
| «Не хватило видеопамяти …» или генерация вдруг очень медленная | видеопамять заняли другие программы; на Windows драйвер при нехватке VRAM уходит в общую память и всё замедляется в разы | закройте лишнее, нажмите **Освободить VRAM**; меньше размер/разрешение; сервер сам переходит в экономный режим. Отключить «уход в общую память»: Панель управления NVIDIA → Управление параметрами 3D → *CUDA — политика резерва системной памяти* → *Предпочитать отсутствие резерва* (для python.exe из `runtime\venv`) |
| «Не хватает оперативной памяти …», `WinError 1455`, «файл подкачки слишком мал» | модели берут на пиках до 11–15 ГБ RAM; при фиксированном маленьком файле подкачки Windows отказывает | закройте лишние программы; файл подкачки — «Размер по выбору системы» |
| Картинка с неверным числом деталей («✗ видно 4 колка») | нейросеть нарисовала не то (Z-Image рисует домбру как пипу) | для предметов с чертежом — точный чертёж; иначе ещё варианты или своё фото-референс |
| Модель из студии не появилась в Blender | Blender закрыт, выключен приём моделей, другой адрес сервера | Blender должен быть открыт; Preferences → Add-ons → DroneGen → «Принимать модели из студии» |
| «Недоступно: не скачаны веса …» | установка прервалась | `python install.py` ещё раз — докачает только недостающее |
| «нужна видеокарта NVIDIA …» | лёгкий профиль или нет CUDA | используйте чертежи и «Силуэт → объём» или переустановите с `--profile full` |
| «Сервер не на этом компьютере, а доступ в сеть у Blender выключен» | адрес сервера не 127.0.0.1 | Preferences → System → Network → **Allow Online Access** |
| Установка: «uv не смог установить Python» | сбой загрузки | повторите установку; при повторе — интернет/антивирус |

Логи: `runtime\logs\server.log` (сервер), `runtime\logs\llama-server.log` (локальная модель чата),
`runtime\logs\install.log` (установка), консоль Blender (Window → Toggle System Console) — для аддона.

## Офлайн и приватность

После установки сервер работает **без интернета** (`HF_HUB_OFFLINE=1`): веса читаются из `runtime\models`, rembg —
из `runtime\models\u2net`. Флаг `--online` разрешает сеть. Проверка:
`runtime\venv\Scripts\python -m dronegen_server.selfcheck --offline --models`. В облако ничего не уходит, пока в
настройках студии не включён режим «Облако (Claude API)».

Единственное, что студия сама ищет в сети, — внешний вид персонажа, которого назвал пользователь: в
`ru.wikipedia.org` / `en.wikipedia.org` уходит **только название** («Молния Маквин»), картинка статьи скачивается с
`upload.wikimedia.org`. Ни текст чата, ни ваши картинки туда не отправляются. Выключить: настройки студии → снять
галочку «Искать в интернете, как выглядят персонажи и предметы»; тогда (как и без интернета) ассистент попросит описать
персонажа словами или прикрепить картинку.

## Сервер на другом компьютере

```bash
start_server.bat --host 0.0.0.0 --token СЕКРЕТ
```

В настройках аддона: адрес `http://<ip>:8188` и тот же токен; в Blender включите Allow Online Access. Студия —
`http://<ip>:8188/studio/?token=СЕКРЕТ`. Результаты скачиваются через `/files/{name}`, общая папка не нужна.

## API сервера

| Метод | Что делает |
|---|---|
| `GET /health` | версия, бэкенды (доступен ли и почему), GPU и свободная VRAM, очередь, RAM |
| `POST /txt2img` | JSON `prompt, width, height, steps, seed, backend`, необязательно `style` (`render`, `sheet`, `flat` — сервер дописывает слова стиля) → `job_id` |
| `POST /img2mesh` | multipart `image` (или `image_name`) + `backend, remove_bg, mc_resolution`; карточки: `views` (JSON `{вид: файл}`) или `view_front/left/back/right/side`; любые настройки бэкенда — JSON в `params` |
| `POST /cards/split` | `image_name` — лист видов → карточки тех видов, что на нём есть: спереди, сбоку, сзади (повторы отброшены); `figures` — чем оказалась каждая фигура, `notes` — чего не хватает |
| `GET /templates`, `POST /build` | чертежи и их параметры; построить модель `{template, values}` |
| `GET /motions`, `POST /motion/bake` | каталог движений (вид: цикл, поза, разово; нужные части тела; период; параметры); ключи движения для скелета `{skeleton, motion, params, samples}` — сразу, без очереди: локальные кватернионы костей и сдвиг корня |
| `GET /effects`, `POST /effects/build` | виды эффектов; места дронов эффекта `{kind, size, spacing, frame, reserve_at, count, params, points}` — сразу, без очереди: `shape` (места относительно якоря), `reserve` (места в резерве, сопоставленные без пересечений), у брызг `velocity`, замечания |
| `GET /rig/plans`, `POST /rig` | планы тела; скелет для сетки: multipart `mesh` (NPZ с `vertices`, `faces` в осях Blender) или `mesh_name` (GLB из результатов), `method` (`template`), `plan` → задача, в результате кости `{name, role, side, chain, segment, head, tail, parent, deform}`, оси тела, найденные части, замечания |
| `GET /styles` | стили картинок и подходящие им способы 3D |
| `GET /jobs/{id}`, `POST /jobs/{id}/cancel` | состояние задачи, отмена |
| `GET /files/{name}` | скачать результат (PNG, GLB, OBJ) |
| `GET /blender/inbox`, `POST /blender/inbox/{id}/taken\|done` | очередь «В Blender» (для аддона) |
| `/studio/api/…` | проекты, чаты, сообщения, события (SSE), настройки — API окна студии |
| `POST /unload`, `POST /shutdown` | выгрузить модели; остановить сервер (только с этого компьютера) |

Все задачи идут через одну очередь и один рабочий поток: две модели никогда не делят видеопамять. При смене модели
предыдущая выгружается; через 10 минут простоя выгружаются все.

## Устройство и расширение

```
install.py                  установщик (только стандартная библиотека)
start_server.bat / start_studio.bat / .sh
server/dronegen_server/     сервер
  app.py, chat_api.py       HTTP API; API студии (проекты, чаты, SSE, ползунки, очередь «В Blender»)
  jobs.py                   очередь, рабочий поток, выгрузка моделей
  backends/                 mock, silhouette, zimage, sdxl, triposr, hunyuan (mini + mv), parametric
  parametric/               чертежи: shapes.py (примитивы), dombra / shanyrak / yurt / baiterek, registry.py
  rigging/                  скелет: skeleton.py (воксели → средняя линия), roles.py (что есть что: ноги, крылья,
                            руки, голова, хвост, левое и правое), chains.py (кости по ролям),
                            motions.py (каталог движений и их ключи для скелета)
  effects.py                эффекты со своими дронами: контуры, искры, брызги, свои точки; резерв и назначение мест
  agents/                   ассистент (assistant.py), инструменты (tools.py), промпт-инженер, арт-директор,
                            knowledge/*.md — справки о предметах, lookup.py — поиск персонажей в Википедии
  llm/                      провайдеры чата: local.py (llama.cpp + Qwen3-VL), claude.py (облако), images.py
  store.py                  SQLite: проекты, чаты, сообщения, ассеты, очередь Blender; настройки и ключи
  cards.py, postprocess.py  лист видов → карточки; чистка сетки, симметрия, цвета с карточек
  preview.py, quality.py    программный рендер превью; метрики формы
  styles.py                 стили картинок под способы 3D
  studio/                   веб-приложение окна студии (JS без сборки, model-viewer в vendor/)
blender_addon/dronegen/     аддон (только stdlib: urllib, threading)
  link.py                   приём моделей из очереди студии;  studio.py — окно и Alt+Shift+D
  workspace.py              воркспейс DroneGen;  client.py, jobs.py, operators.py, ui.py — панель
  rig.py                    скелет в Blender: арматура по ответу сервера, веса, привязка меша и точек дронов
  motion.py, safety.py      слои анимации → дорожки NLA и полёт; проверка скоростей и расстояний дронов

tests/                      сквозные тесты в Blender (в фоне и с окном)
```

* **Новый чертёж** — функция `build(values) -> trimesh.Trimesh` и таблица параметров в `parametric/`, `register(...)`,
  импорт в `parametric/__init__.py`; ассистент, ползунки и API подхватят его сами. Справке предмета в
  `agents/knowledge/` добавьте строку `template: ключ`.
* **Новый бэкенд** — класс-наследник `Txt2ImgBackend` / `Img2MeshBackend` / `Backend` с `@register` в
  `server/dronegen_server/backends/` и импорт в `backends/__init__.py`.
* **Новая справка о предмете** — файл `agents/knowledge/имя.md`: `names:` (слова, по которым ищется), `style:`
  (`sheet` / `render` / `flat`), описание, что обязательно, типичные ошибки.

### Что пришлось адаптировать

* **TripoSR**: его `requirements.txt` закрепляет `transformers==4.35.0` и `torchmcubes` из git (компиляция, часто ломается
  на Windows). Вместо этого: свежие пакеты, `torchmcubes` заменён шимом на PyMCubes/scikit-image, а веса DINO-ViT
  переименовываются под transformers 5 (там переименовали слои ViT).
* **Hunyuan3D-2**: нужен только код формы (`hy3dgen`), текстуры считаются проекцией с карточек — без CUDA-расширений.
  `pymeshlab` (GPL, нужен лишь их необязательным постобработчикам) заменён заглушкой; веса DINOv2 переименовываются под
  transformers 5; быстрый декодер FlashVDM включён. Стороны карточек: «left» — левый бок самого предмета (вид с +X).
* **Z-Image-Turbo** в bf16 требует ~16 ГБ VRAM. Здесь transformer берётся в GGUF Q4_K_M (4,6 ГБ), текстовый энкодер
  Qwen3-4B (8 ГБ) считается на процессоре и сразу выгружается, эмбеддинги кешируются.
* **Локальная модель чата** — llama.cpp (сборка CUDA 12.4: сборка с CUDA 13.x требует более нового драйвера) и
  Qwen3-VL-8B-Instruct Q4_K_M. Процесс привязан к серверу (job object Windows) и не переживает его.
